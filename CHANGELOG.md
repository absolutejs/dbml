## 0.4.0 — 2026-11-19

### Breaking

- **A table’s triggers, rules, partitions, policies and view query are data** (`DbmlTable`, `DbmlTableDetail`, `detailLine`, `detailWhen`, `tableNoteOf`)
  What a table is and does beyond its columns is now data: `table.details` lists its kind (a view with its query, a materialized view, a partitioned or foreign table), what it is partitioned by and its partitions, what it inherits from, its triggers and rules (each with its name and definition on one line), and row-level security with its policies. The printed DBML is the same: the printer writes each detail as a line of the table’s note, as before. `table.note` now holds only the table’s own note (its comment).
  _Migration:_ Read `table.details` for a table’s triggers, rules, partitions, policies and view query; for the whole note as printed, call `tableNoteOf(table)` instead of reading `table.note`.

## 0.3.0 — 2026-11-19

### Added

- **Drizzle: filtered relations, and many relations with their own keys**
  A Drizzle 1.0 relation with a `where` filter says its filter in the reference’s note, and a many declared with its own from and to becomes a link from the key to the one side, as a foreign key would be.
- **Metadata blocks for tables and columns** (`DbmlColumn`, `DbmlTable`, `DbmlMetadata`, `groupBySchema`, `isUniqueSet`)
  Tables and columns take `metadata`, a record of string, number and boolean facts, printed as DBML `Metadata Table` and `Metadata Column` blocks. A view dependency over several columns prints as one edge per column. groupBySchema and isUniqueSet are shared by every reader.
- **Live MySQL, MariaDB and SQLite databases** (`fromMysql`, `FromMysqlOptions`, `MysqlQuery`, `fromSqlite`, `FromSqliteOptions`, `SqliteQuery`)
  `@absolutejs/dbml/mysql` reads a live MySQL or MariaDB database from information_schema: exact column types, enums and sets, defaults, generated and invisible columns, prefix, expression and invisible indexes, checks, foreign keys, partitions, triggers, views with the tables they read, routines, scheduled events, and each table’s engine, collation and grants. `@absolutejs/dbml/sqlite` reads a SQLite database from its pragmas and CREATE statements: the row id key and AUTOINCREMENT, collations, generated columns, checks, expression and partial indexes, strict and WITHOUT ROWID tables, views and triggers. The CLI takes `--mysql <url>`, `--sqlite <file>` and `--statistics`, and only reads.
- **Postgres: triggers, rules, functions, domains, extensions, partitions, grants and more** (`FromPostgresOptions`)
  fromPostgres now reads what a database holds beyond tables, keys and indexes. On tables: owner, grants, unlogged, storage options, a foreign table’s server and options, and inheritance as metadata; triggers, rules and each partition with its bounds as lines of the note. On columns: collation, compression, the domain a column is of, and an identity sequence that doesn’t start at one. On indexes: nulls ordering, operator classes, collations and NULLS NOT DISTINCT. Functions and procedures, domains, composite types, extensions and event triggers come as sticky notes, a view’s lineage names the columns it reads, and anything an extension installed stays out. `statistics: true` adds estimated rows and size; `groups: 'schema'` groups tables by schema.

## 0.2.0 — 2026-11-19

### Added

- **Name the app’s own schema without qualifying every table** (`FromPostgresOptions`, `withDefaultSchema`)
  fromPostgres takes a `defaultSchema`: the schema whose tables, enums and references are named without it, the way a query run there names them (`public` by default). An app whose tables live in their own schema now reads `"orders"` rather than `"app_schema"."orders"` on every table, while tables in any other schema, `public` included, keep their schema so two schemas never look alike. withDefaultSchema(model, schema) does the same to any model.

## 0.1.0 — 2026-11-19

### Added

- **Turn a Drizzle schema, or a live Postgres database, into DBML**
  fromDrizzle reads a Drizzle 1.0 schema in any of its dialects (PostgreSQL, MySQL, SQLite, SingleStore, SQL Server, CockroachDB): tables, enums (named and inline), every column type and array, identity, serial and generated columns, defaults, composite and named keys, unique constraints, indexes with their order, method, expressions and predicates, checks, foreign keys with their actions, row-level security and policies, views and materialized views with lineage, sequences and roles, and both styles of relations, with app-only relations as inactive refs and many-to-many ones as <> refs. fromPostgres reads the same from a live database's catalogs, whatever made it, with comments as notes and optionally its first rows as Records. printDbml writes either as DBML, and every construct is tested against the official DBML parser. The absolute-dbml command does both from a terminal.
